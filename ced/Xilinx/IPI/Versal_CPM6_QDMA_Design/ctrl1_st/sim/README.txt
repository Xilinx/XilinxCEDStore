================================================================================
  Versal CPM6 QDMA Gen6 PIPE Simulation -- CTRL1 EP, Streaming
  Controller: CTRL1 only (Endpoint)
  DMA mode  : Streaming (H2C/C2H AXI4-Stream, C2H completions)
  Mode      : PIPE Simulation
================================================================================

Steps to run CPM6 QDMA (CTRL1) streaming simulation

1.  The following tool versions are needed for running the CPM6 QDMA simulation. Add these tools to
    your PATH environment variable so that they can be accessed from CED Simulation scripts and add
    the necessary licenses or point to the license servers needed to access them as explained in
    their respective manuals.
    a. Vivado            - 2026.1.1
    b. VCS / Verdi       - X-2025.06-SP2 (Verdi 2025.06-SP2-2 optional, waveforms)
    c. UVM Library       - 1.1
    d. Avery PLI         - 2025.3_1, from the version-matched bundle (see step 3a)
    e. Avery apci-xactor - 2025.3_1

2.  Download and unzip the CPM6 Secure IP package (provided separately) from
    https://account.amd.com/en/member/cpm6-simulation.html

    NOTE: use the package built for the Vivado version in step 1a. The
    directory layout the package ships differs between releases, and the
    cpm6_sip.f generated by Vivado expects the layout of its own release --
    mixing versions fails at elaboration with "Error-[SFCOR] Source file
    cannot be opened" on cpm6_001.svp / cpm6_002.svp / CPM6.v.

3.  Set the environment variables listed below (tcsh or bash shell):

    a. Set "AVERY_PLI" to the Avery PLI binary location, e.g.
         tcsh: setenv AVERY_PLI <path to avery pli install>
         bash: export AVERY_PLI=<path to avery pli install>

       IMPORTANT: AVERY_PLI must come from the same bundle as AVERY_PCIE and
       AVERY_SIM -- i.e. the avery_pli-<ver> that sits alongside
       apcievip-<ver> in the auciexactor tree, not a standalone
       avery/pli/avery_pli-<ver> install. A mismatched PLI -- or a dead
       entry in SALT_LICENSE_SERVER / MGLS_LICENSE_FILE -- stops the Avery
       license client completing feature checkout, and the run then stalls
       silently: tracker_*.log files stay at 0 bytes, no avypcie banner is
       printed, and no error is issued. A salt_mgls process spinning at
       ~99% CPU alongside an idle simv is the signature.

    b. Set "AVERY_PCIE" to the Avery PCIe source libraries, e.g.
         tcsh: setenv AVERY_PCIE <path to avery apci xactor install>
         bash: export AVERY_PCIE=<path to avery apci xactor install>

    c. Set "CPM6_SECUREIP" to the directory where the CPM6 Secure IP
       package was extracted, e.g.
         tcsh: setenv CPM6_SECUREIP <path to extracted cpm6 secureip>
         bash: export CPM6_SECUREIP=<path to extracted cpm6 secureip>

    d. Set "VIVADO_CLIBS" to the directory containing your precompiled VCS
       simulation libraries for the selected Vivado/VCS version, e.g.
         tcsh: setenv VIVADO_CLIBS <path to compiled simlibs>
         bash: export VIVADO_CLIBS=<path to compiled simlibs>

       IMPORTANT: this sets synopsys_sim.setup's OTHERS= line. If unset/wrong,
       OTHERS=?/synopsys_sim.setup and compile.sh fails with Error-[SETUP_INCLUDE_ERR].

    Verify:
         echo $VCS_HOME       # should show X-2025.06-SP2 path
         echo $AVERY_PLI      # must be the bundle-matched install (see NOTE above)
         echo $AVERY_PCIE     # should show apcievip-2025.3_1 path
         echo $CPM6_SECUREIP  # should show your extracted path
         echo $VIVADO_CLIBS   # should show your compiled simlib path

4.  Create the Vivado project from this CED with the Streaming DMA mode.

    This single step builds the block design, imports the RTL, AND generates
    the VCS simulation scripts (compile.sh/elaborate.sh/simulate.sh) under
    <project_name>.sim/sim_1/behav/vcs/, and copies the simulation files
    alongside the Vivado project as <project_name>/sim -- no separate
    "launch_simulation" step is needed.

    NOTE: use part xc2vp3602-vsvc3340-2MHP-e-S (not 2MP-e-L or 2LHP-e-S).

    The sim/ directory contains:
      Makefile        -- build and simulation targets (see step 5)
      README.txt      -- this file
      tb_files.f      -- testbench file list
      verif/          -- DUT instantiation, UVM agents, and the QDMA test
                         package (verif/test/test_qdma_h2c_c2h_st_Mfnc_MQ.sv)
      tb/             -- the shared PCIe UVM environment and test framework
      avery_vcs.f, cpm6_sip.f, uvma_agents.f, uvma_agents/, lib/
                      -- Avery VIP, Secure IP and utility-agent file lists,
                         and the C shared libraries used by the build

5.  Run simulation:

         cd <project_name>/sim

         make cos                    -- compile + optimize + simulate the default
                                        preset (CONFIG=st_pfch_both_pidx7)
         make cos CONFIG=st_pfch_both_8k_1q
                                     -- same, with the 8 KB single-queue preset
         make s PARG_EXTRA="+PIDX=53 +PKT_COUNT=53"
                                     -- re-simulate with extra plusargs, no rebuild
         make s SEED=<n>             -- reproduce an exact prior run bit-for-bit
                                        (the seed used is printed in vcs.sim.log)
         make smoke                  -- re-simulate the default test and preset
         make distclean              -- wipe all compiled libs and start completely
                                        fresh (use if a build gets stuck/inconsistent)
         make h                      -- show help with all options

    Waveforms: DUMP=1 DEBUG=1 VERDI=1 (the default) writes waves.fsdb, with the
    dump start delayed past CDO load (see DUMP_START_TIME). Use DUMP=0 DEBUG=0
    for faster batch runs; DEBUG changes need a rebuild (make cos).

    Link width: the X2 or X8 width chosen when the project was created from
    the CED is read from the project's defines.sv; nothing to set here.

    IMPORTANT: plusargs must be passed inside PARG_EXTRA="...". A bare
    +ARG=VAL on the make command line is silently dropped and the run falls
    back to the Makefile defaults.

    Expected outcome:
      Simulation completes with UVM_ERROR : 0 and UVM_FATAL : 0 in the report
      summary at the end of vcs.sim.log, and the DRV_SEQ SUMMARY line shows
      every H2C request and C2H packet retired and fully checked.

      With several queues active in both directions (st_pfch_both_pidx7),
      some requests take longer than the testbench's 40 us per-step bound.
      These are reported as UVM_WARNING [DRV_STEP_TIMEOUT] ... [stricter-than-
      driver, demoted] and counted in the DRV_CHK SUMMARY; the data is
      unaffected. To report them as UVM_ERROR, run with DRV_CHK_WARN= (empty).

    To force-recompile only the Vivado DUT lib, clear contents only -- never
    remove vcs_lib itself:
      rm -rf <project>.sim/sim_1/behav/vcs/vcs_lib/*
    (vhdlan, used for VHDL libs like proc_sys_reset, can't recreate a missing
    vcs_lib parent and fails with Error-[DLIB_CANT_CREATE_DIR].)

--------------------------------------------------------------------------------
PRESETS (CONFIG=...)
--------------------------------------------------------------------------------
Both presets run H2C and C2H stream DMA with C2H descriptor prefetch,
descriptor credits supplied by the testbench on dsc_crdt_in, C2H completions,
and the driver sequence in poll mode (+TEST_MODE=DRV_SEQ, +IRQ_EN=0).

  st_pfch_both_pidx7   (default) 1 PF + 4 VFs, one queue each; 7 packets of
                       512 B per direction per queue.
  st_pfch_both_8k_1q   1 PF queue; 7 packets of 8 KB per direction. Each 8 KB
                       H2C request is split into two 4 KB descriptors.

--------------------------------------------------------------------------------
GENERATED LOGS
--------------------------------------------------------------------------------
Each run writes the following into its run directory under <project_name>/sim:

  vcs.sim.log               -- full simulation transcript: UVM report summary,
                               the seed used, and the [TEST_DONE] line. Check the
                               UVM_ERROR / UVM_FATAL counts here first.
  cpm6_qdma_dbg.log         -- per-event QDMA log: descriptor fetch, queue
                               arbitration, writeback, MSI-X, and the
                               DMA_SCOREBOARD byte-count verdict.
  tracker_phy_vip<n>.log    -- Avery PCIe VIP, physical layer: LTSSM transitions,
                               link training, lane status.
  tracker_phy_flit_vip<n>.log -- flit-mode physical layer (Gen6 is flit mode).
  tracker_dll_vip<n>.log    -- data link layer: DLLP exchange, ACK/NAK, credits.
  tracker_dll_flit_vip<n>.log -- flit-mode data link layer.
  tracker_tl_vip<n>.log     -- transaction layer: every TLP sent and received.
  tracker_cfg_vip<n>.log    -- config-space accesses during enumeration,
                               including SR-IOV VF setup.
  tracker_trans_vip<n>.log  -- VIP transaction-level view, correlating each
                               request with its completion.
  waves.fsdb                -- Verdi waveform database (DUMP=1 DEBUG=1 VERDI=1).

The <n> in tracker_*_vip<n>.log is the VIP port index. When the link or
enumeration misbehaves, start with tracker_phy_vip<n>.log for link training,
tracker_cfg_vip<n>.log for enumeration, and tracker_tl_vip<n>.log for the DMA
TLPs themselves.

--------------------------------------------------------------------------------
AVAILABLE TESTS
--------------------------------------------------------------------------------
test_qdma_h2c_c2h_st_Mfnc_MQ -- H2C and C2H stream DMA across PF and/or VF
queues. With +TEST_MODE=DRV_SEQ (used by both presets) each queue is set up and
serviced the way the QDMA Linux driver does it: context programming, ring
doorbells, C2H prefetch and completion-ring processing. H2C payload is checked
on the H2C stream ports at the block design boundary; C2H payload, completion
entries and status writebacks are checked as they are written to host memory.
See the test file header for the full plusarg list, and pass plusargs via
PARG_EXTRA as shown in step 5.

test_qdma_mem_tlps -- writes five data patterns to the QDMA global scratch
register (PF0 BAR1 + 0x244) with PCIe memory-write TLPs, reads each back with a
memory-read TLP and compares. No DMA is run. Run it with make s TEST=test_qdma_mem_tlps.

--------------------------------------------------------------------------------
RUNNING ON HARDWARE
--------------------------------------------------------------------------------
On hardware the QDMA IP core is driven by the QDMA Linux driver
(dma_ip_drivers), which supplies the kernel modules and the dma-ctl user-space
tool used to create queues, program descriptor rings, and run H2C/C2H
transfers. Driver sources, build instructions and usage documentation:

  https://xilinx.github.io/dma_ip_drivers/

C2H data comes from the C2H generator in the PL. Its registers are in PF BAR2,
offset 0; the PF programs it for its own queues and for VF queues. Port 0:

  0x00  QID          absolute queue ID of the next burst
  0x04  LEN          packet length in bytes (non-zero multiple of 64)
  0x08  CONTROL      write 0x2 (bit 1) to START a burst
  0x20  NUM_PKT      packets per burst
  0x100 EXT_CONTROL  read: bit 0 BUSY, bit 1 STOPPED; write bit 0 to STOP
  0x1C0 ID           reads 0x43324843

The full map, including ports 1-3, is in the header of c2h_source_cfg.sv.

Example: one stream queue on the PF, 7 packets of 512 B in each direction.

  dma-ctl qdma01000 q add idx 0 mode st dir bi
  dma-ctl qdma01000 q start idx 0 dir h2c
  dma-ctl qdma01000 q start idx 0 dir c2h
  dma-to-device -d /dev/qdma01000-ST-0 -s 512 -c 7
  dma-ctl qdma01000 reg write bar 2 0x00 <qid>
  dma-ctl qdma01000 reg write bar 2 0x04 512
  dma-ctl qdma01000 reg write bar 2 0x20 7
  dma-ctl qdma01000 reg write bar 2 0x08 0x2
  dma-from-device -d /dev/qdma01000-ST-0 -s 512 -c 7 -f c2h.bin
