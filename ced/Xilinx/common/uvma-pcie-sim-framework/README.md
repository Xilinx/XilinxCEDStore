# uvma-pcie-sim-framework
This repository builds a framework such that a user can simulate their AMD PCIe IP DUT, such as CPM or PL-PCIe, with a VIP (from a 3rd party vendor or AMD IP) in a UVM TB environment. The framework is designed to be extremely flexible to allow customers to focus on simulating what they care about, which is specific to their Vivado design. Making the testbench, wiring the connections, generating clocks and resets, and enumerating the PCIe bus are common functions that _any_ PCIe simulation will need, so the framework is designed to get to that point easily and then a customer can start developing on top of that.

When attempting a Vivado simulation, Vivado creates the DUT and natively creates the simulation scripts - compile.sh, elaborate.sh, simulate.sh - along with additional simulation metadata. The framework does everything through a Makefile ([example](cpm6/sim/Makefile)) and several flexible arguments passed to it.  After Vivado creates the simulation scripts, Vivado is no longer needed and the framework does not employ it at all. The framework parses the compile.sh to understand all of the DUT files needed, then compiles the framework and the necessary VIP along with the DUT. Optimizing (elaborating) and simulating are, again, steps performed through the Makefile. To actually perform a simulation in its entirety, this framework is typically placed alongside the Vivado project, then a few Makefile variables need to be specified so that the framework becomes aware of the Vivado project. Typically, a project-specific wrapper Makefile is used that simply statically sets these variables and then _include_-s the framework Makefile. After getting access to this repository, the Makefile will have plenty of helpful information about its targets and variables, which you can see by running the _h_ or _help_ (identical) targets, or running make with no target at all, which defaults to the aforementioned one.

Summarizing the typical flow into a single sentence: a user typically needs to supply just a few variables to Make along with a single target to get a simulation running. There are default values embedded into the Makefile itself and several can be permanently overridden by environment variable. The priority for variable assignment goes like this: provided on command line > environment variable (not all options support this) > Makefile default. I will show an example command line call below to run a simulation making explicit variable assignment even though many are left at default or statically assigned in the typical use case. The bracketed arguments - using standard POSIX utility syntax, meaning optional - are ones typically not used each call. Running a simulation requires calling three Makefile targets: c[ompile], o[ptimize], s[imulate], for which "cos" is an alias to perform each of those steps in series. For additional information, examine the Makefile itself or its h[elp] target output printed to the terminal.
```
$> make cos TEST=<testname> [SIM=questa|vcs] [PCIE_LINK=PIPE|SERIAL] [DEFINES=(comma separated list)] [PLUSARGS=(comma separated list)] [GUI=-1|0|1|2|3]
```
